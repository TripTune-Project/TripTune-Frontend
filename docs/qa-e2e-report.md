## 발견된 결함

### 1. 홈 검색: 빈 검색어에 아무 안내가 없다 (메인003) — 중간

- **위치**: `src/components/Feature/Home/HomePageSearch.tsx` — `handleSearch`
- **기대**: "검색어를 입력해주세요" 메시지 표시
- **실제**: `if (!searchTerm.trim()) return;` — 조용히 아무 일도 일어나지 않음
- **참고**: 같은 케이스인 여행지 탐색 페이지(탐색003)는 정상적으로 안내한다. 두 화면의 동작이 불일치.

### 2. 여행지 탐색: 검색 버튼을 누르면 빈 키워드로 API가 나간다 (탐색001 연관) — 중간

- **위치**: `src/app/Travel/page.tsx` — `handleSearch`
- **원인**: 버튼은 `refetchSearch()`를 즉시 호출하는데, 쿼리 키의 `keyword`는 800ms 디바운스된 값이라 클릭 시점엔 아직 `''`
- **실제**: `POST /api/travels/search` → `400 {"message":"검색어는 필수 입력 값입니다."}`
- **영향**: 검색할 때마다 불필요한 400 요청이 1건씩 발생. 결과 표시는 디바운스 후 재요청으로 덮이므로 사용자 눈에는 안 보임.
- **수정 방향**: 버튼 클릭 시 디바운스를 건너뛰고 `searchTerm`을 즉시 반영하거나, `keyword`가 빈 값이면 요청을 보내지 않는다.

### 3. 여행지 상세: 조회 실패 시 로딩 스피너가 사라지지 않는다 (세부목록009) — 높음

- **위치**: `src/app/Travel/[placeId]/page.tsx`
- **기대**: "데이터를 불러오지 못했습니다. 다시 시도해주세요" 안내
- **실제**: 네트워크 오류를 주입하면 `DataLoading`이 20초 이상 계속 표시됨 (오류 상태 처리 없음)

### 4. 북마크 상태가 여행지 목록·상세에 반영되지 않는다 (북마크002·003·005) — 높음

API로 직접 확인한 결과:

| 요청                                  | 결과                                 |
| ------------------------------------- | ------------------------------------ |
| `POST /api/bookmarks {placeId: 7931}` | `200 성공`                           |
| `POST /api/travels?page=1` (인증 O)   | `bookmarkStatus: false`              |
| `GET /api/travels/7931` (인증 O)      | `bookmarkStatus: false`              |
| `GET /api/members/bookmark`           | 총 1건, placeId 7931 **정상 등록됨** |

- 북마크 등록 자체는 성공하고 마이페이지 북마크 목록에도 나온다. 그런데 **여행지 목록/상세 응답의 `bookmarkStatus`가 항상 `false`**라 아이콘이 빈 상태로 남고, 새로고침해도 유지되지 않는다.
- 프론트는 응답값을 그대로 렌더링하므로 **백엔드 쪽 확인이 먼저 필요**하다.
- 영향 케이스: 탐색004·005, 세부목록003, 북마크002·003·005·006

### 5. 푸터 이메일이 클릭되지 않는다 (메인010) — 낮음

- **위치**: `src/components/ClientLayout.tsx`
- **기대**: "이메일 및 GitHub 페이지로 정상적으로 이동"
- **실제**: GitHub는 `<a href>`지만 이메일(`triptunehost@gmail.com`)은 평문. `mailto:` 링크가 아니다.
- **덤**: GitHub 링크에 `target="_blank"`가 없어 클릭하면 같은 탭에서 앱을 벗어난다.

## 관찰 (결함은 아니지만 짚어둘 것)

### 홈 캐러셀 첫 클릭이 씹힌다

인기/추천 여행지 섹션은 `dynamic()` import다. 인기 섹션만 먼저 뜬 상태에서 화살표를 누르면,
뒤늦게 마운트된 추천 섹션 때문에 Swiper가 재초기화되며 **첫 클릭이 무시되는 경우**가 있다.
로컬·운영 양쪽에서 재현됐고, 페이지가 뜨자마자 화살표를 누르는 실사용 상황에서도 나올 수 있다.
테스트(메인005)는 목표 인덱스에 닿을 때까지 최대 5회 재시도하도록 해서 이 경합을 흡수한다.

### 환경

- `.env`에 `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`가 없어 **로컬에서만** 지도가 "죄송합니다. 문제가 발생했습니다."로 렌더된다. 운영은 정상.
- 일부 여행지는 이미지가 없어 "이미지가 없습니다." 플레이스홀더가 뜬다(정상 동작). 세부목록002는 이 경우를 허용한다.

## 자동화하지 않은 케이스와 이유

각 spec 파일 하단 주석에 케이스 ID와 함께 기록해 두었다. 분류는 셋뿐이다.

1. **되돌릴 수 없는 운영 데이터 변경** — 회원가입 완료, 계정 탈퇴, 이메일·비밀번호·프로필 실제 변경, 일정 생성·삭제·나가기, 일정에 여행지 추가. → 수동 QA
2. **서드파티 / 실시간 의존** — 네이버·카카오 간편 로그인(외부 인증 화면), 인증·비밀번호 재설정 메일 수신, STOMP 채팅과 다중 계정 동시 편집, Google Maps 마커 클릭(canvas라 DOM 셀렉터 없음). → 수동 QA
3. **기능 미구현 / 재현 불가** — 메인007(추천 여행지 더보기 버튼 없음), 탐색008(Pagination이 범위 밖 버튼을 만들지 않음), 캘린더009·010(DatePicker가 역순 선택을 원천 차단).

## 산출물

```
cypress/videos/*.mp4              # 로컬 dev 대상 전체 녹화 (무음, 텍스트 자막)
cypress/screenshots/**/*.png      # 로컬 케이스별 fullPage 캡처 + 실패 시 자동 캡처
cypress/videos-prod/*.mp4         # 운영 대상 전체 녹화
cypress/screenshots-prod/**/*.png # 운영 캡처
```

녹화에는 음성이 없고, `cy.step('탐색003 · 빈 검색어로 검색 버튼 클릭')` 형태로 지금 검증 중인 QA 케이스가 화면 하단 배너에 텍스트로 표시된다. 스크린샷에는 이 배너가 나오지 않는다.

## 실행 방법

```bash
# 로컬 dev 대상
yarn local      # 터미널 1: dev 서버 (포트 5814)
yarn cy:run     # 터미널 2: 전체 E2E 실행 + 녹화
yarn cy:open    # 브라우저에서 개별 spec 실행

# 운영 대상
npx cypress run --config \
  baseUrl=https://www.triptune.co.kr,videosFolder=cypress/videos-prod,screenshotsFolder=cypress/screenshots-prod
```

`cypress.env.json`에 QA 계정 정보가 들어가므로 **커밋하지 않는다**(`.gitignore` 등록 완료).
새로 받은 사람은 `cypress.env.example.json`을 복사해 값을 채우면 된다.
